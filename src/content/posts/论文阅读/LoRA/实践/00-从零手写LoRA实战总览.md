# 从零手写 LoRA 实战总览：架构设计与模块解耦

> 在理论篇中，我们推导了 LoRA 的低秩参数化、SVD 能量谱、显存账单与训练动力学。但在工程实践中，如果直接调用 `peft` 或 `transformers.Trainer`，底层的梯度阻断、dtype 转换、动态模块替换和 Loss Masking 机制都会被封装成黑盒。本实战系列脱离高级封装，仅依赖 **PyTorch 原生 API**，为 `Qwen2.5-0.5B-Instruct` 纯手工搭建一套可运行、可训练、可合并的端到端 LoRA 微调系统。

---

## 一、 任务目标与技术基准

我们以经典的**中文新闻标题生成（SFT 摘要任务）**为例进行全流程贯通：
- **基座模型**：`Qwen2.5-0.5B-Instruct`（约 5 亿参数，BF16 精度，占用显存约 1GB）；
- **微调数据**：LCSTS 新闻摘要数据集（输入正文，输出精炼标题）；
- **微调目标**：给模型的 7 个核心线性投影层（$W_q, W_k, W_v, W_o, W_{\text{gate}}, W_{\text{up}}, W_{\text{down}}$）注入 LoRA 适配器，将可训练参数压缩至 **$0.4\%$** 左右；
- **交付结果**：训练收敛后，将低秩权重无损合并回原模型，导出独立的单体模型并进行自回归生成评测。

---

## 二、 全流程端到端架构设计

整个微调系统的执行流水线与张量流转关系如下：

```
[原始 Qwen2.5-0.5B 模型] (冻结全部权重 W0)
          │
          ▼
┌────────────────────────────────────────────────────────┐
│ 1. 动态模块注入 (load.py)                                │
│ 遍历结构树，将指定 nn.Linear 替换为手写的 LoRALinear        │
│ 输出：可训练参数仅占 0.4% 的 LoRA 复合模型                │
└────────────────────────────────────────────────────────┘
          │
          ├─────────────────────────┐
          ▼                         ▼
┌──────────────────────────┐  ┌──────────────────────────┐
│ 2. SFT 数据管线 (data.py)│  │ 3. 原生训练引擎 (train.py)│
│ 构建 Qwen ChatML 模板     │  │ 仅将 A/B 参数传给 AdamW  │
│ 对 Prompt 区域做 -100 掩码│──>│ 前向计算 + Loss 梯度反传   │
│ 输出：对齐的 Batch Tensor  │  │ 输出：收敛的 LoRA 权重    │
└──────────────────────────┘  └──────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────┐
│ 4. 权重无损合并与导出 (model_utils.py)                   │
│ 计算 W_new = W0 + (α/r) * (B @ A)，还原为标准 nn.Linear   │
│ 输出：零额外推理延迟的完整独立权重                       │
└────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────┐
│ 5. 效果评测与自回归生成 (test.py)                        │
│ 加载合并后模型，输入真实新闻测试标题生成泛化表现          │
└────────────────────────────────────────────────────────┘
```

## 三、 模块解耦与职责清单

为了保证代码具备高可维护性与清晰的工程边界，系统划分为 5 个独立模块：

| 模块文件 | 核心函数 / 类 | 职责与边界 |
| :--- | :--- | :--- |
| **`lora.py`** | `LoRALinear(nn.Module)` | 自定义 LoRA 线性层：封装冻结原矩阵、初始化 $A$ 与 $B$、定义前向双路并行计算与 $\frac{\alpha}{r}$ 缩放。 |
| **`load.py`** | `inject_lora()` / `print_trainable_parameters()` | 动态反射注入：遍历模型树，精准识别 target 线性层并替换为 `LoRALinear`，统计可训练参数占比。 |
| **`data.py`** | `build_prompt()` / `TitleDataset(Dataset)` | SFT 数据集与掩码：格式化 ChatML 提示词，实现 **Loss Masking（Prompt 部分填 `-100`）** 与动态 Padding。 |
| **`model_utils.py`** | `merge_lora_into_model()` / `generate_title()` | 权重合并与生成工具：将 $\Delta W$ 永久合入 $W_0$ 并替换回标准 `nn.Linear`；封装自回归流式生成。 |
| **`train.py`** | `main()` | 训练主入口：串联加载、注入、数据加载、原生 PyTorch 训练循环与模型持久化保存。 |
| **`test.py`** | `main()` | 评测脚本：载入合并后模型，使用多领域新闻真实文本测试输出质量。 |

## 四、 核心工程准则

在编写具体代码之前，必须先确立以下三条工程铁律：

1. **精度与设备严密对齐（Dtype & Device Alignment）**：
   大模型权重通常为 `torch.bfloat16` 或 `torch.float16`，手写新建的参数矩阵必须显式继承原层 `dtype`，否则在 GPU 矩阵乘法中会触发运行时异常。
2. **非侵入式热插拔（Non-intrusive Injection）**：
   不硬编码修改模型的源码文件，而是通过 PyTorch 的子模块反射机制动态替换节点，保证对任意 HuggingFace 模型的通用性。
3. **Loss 计算范围隔离（Strict Loss Masking）**：
   在自回归 SFT 中，模型绝对不能对用户输入题干（Prompt）计算 Loss，只有答案（Target）区域才产生梯度信号。
