# Qwen 架构解剖：从 token 到 logits 的整机系统图

> 承接 [[论文阅读/qwen/01-qwen主线]]：01 回答了"为什么是 Decoder-Only"，本篇回答"整体长什么样"——把整机拆成五个模块，逐个讲清它是什么、为什么存在、数据怎么流过去。这篇是全系列的**地图**，单层算子拆在 [[论文阅读/qwen/03-qwen-decoder-block]]，训练/推理/代码分别在 04/05/06。索引见 [[论文阅读/qwen/00-qwen阅读地图]]。

## 整机五模块

Qwen2-0.5B 的完整结构，自底向上只有五块：

```text title="full_architecture.txt"
Input tokens (T 个 token id)
      │
      ▼
① Embedding 查表 ──>  H⁰ ∈ ℝ[T, 896]
      │
      ▼
┌──────────────────────────────────────────────────────────┐
│ ② 24 × DecoderLayer (结构完全相同，参数各自独立)           │
│                                                          │
│   H^(l) ──> self_attn 子层 ──> mlp 子层 ──> H^(l+1)       │
│            (上下文交互)        (知识变换)                  │
│                                                          │
│   每个子层 = Pre-RMSNorm → 变换 → 残差相加                 │
└──────────────────────────────────────────────────────────┘
      │
      ▼
③ final RMSNorm ──>  H^(24) ∈ ℝ[T, 896]
      │
      ▼
④ lm_head (151936 × 896) ──> logits ∈ ℝ[T, 151936]
      │
      ▼
⑤ 采样 ──> 下一个 token id
```

这张图是整篇的骨架，五个模块下面逐个拆。全程只有两种形状：**$(T, 896)$（向量序列）** 和 **$(T, 151936)$（词表分数）**——除 lm_head 外，没有任何一个模块改变主干维度。

## ① Embedding 查表：token 变成向量的瞬间

输入是一串 token id（整数），Embedding 层把它们变成向量。

$$
H^0 = E[t] \in \mathbb{R}^{T \times 896}, \qquad E \in \mathbb{R}^{151936 \times 896}.
$$

**"查表"就是行选择**：$E$ 的每一行是一个 token 的 896 维向量，输入的第 $i$ 个 token id $t_i$ 决定取 $E$ 的第 $t_i$ 行。151936 行对应 151936 个词表项——词表越大，这张表越贵（151936 × 896 × 2 字节 ≈ 272 MB，占全模型 27.6%）。

注意两个细节：

- **它没有上下文**：查表是逐 token 独立的，$t_1$ 和 $t_5$ 查的是同一张表，互不影响。上下文是后面 24 层的事。
- **它是 tied 的伏笔**：输入用这张表，输出的 lm_head 也复用这张表（`tie_word_embeddings=true`），同一份 272 MB 只存一次。为什么能共享，见第 ④ 模块。

## ② 24 × DecoderLayer：整机的主体

这是全模型 72.4% 参数的所在。24 层**结构完全相同、参数完全独立**——每层有自己的一份 $W_Q, W_K, W_V, W_O, W_{\text{gate}}, W_{\text{up}}, W_{\text{down}}$，共 7 × 24 = 168 个矩阵，互不共享。

每层的内部结构固定是**两个子层**，串行执行：

```
H^(l) ──> [RMSNorm → self_attn] ──> (+) ──> [RMSNorm → mlp] ──> (+) ──> H^(l+1)
          (Pre-Norm + 注意力)   残差   (Pre-Norm + SwiGLU)  残差
```

- **self_attn 子层**：做 token 间的信息交换。每个 token 通过注意力"看"其他 token，把上下文信息融进自己的表示。内部是 QKV 投影 → RoPE → 缩放点积 → 输出投影，逐算子拆解见 [[论文阅读/qwen/03-qwen-decoder-block]]。
- **mlp 子层**：做每个 token 自身的知识变换。把表示升到 4864 维、过 SwiGLU 门控、再压回 896 维——模型的事实知识主要存在这里。
- **Pre-Norm + 残差**：每个子层先归一化再变换，变换结果加回输入。残差让梯度可以直通，是 24 层能堆起来的前提。

**为什么是 24 层？** 0.5B 的参数量是主要约束——层的宽度（$d_{\text{model}}=896$）和深度（$L=24$）相乘决定参数规模，$896 \times 24$ 的搭配是在 5 亿参数预算下"宽度 × 深度"的平衡点。更大的模型（7B）用 28 层但 $d_{\text{model}}=3584$——深度增长慢于宽度增长，因为宽度决定单层的计算密度，深度决定表示的分层能力。

**24 层为什么"一模一样"？** 结构同构但功能分化——浅层处理局部语法，深层处理长程语义和推理。这是训练后涌现的分工，不是设计时人为分配的（详见 01 的"功能分化"节）。

## ③ final RMSNorm：收尾的尺度控制

最后一层输出 $H^{(24)}$ 不直接接 lm_head，先过一层 RMSNorm：

$$
H^{\text{final}} = \operatorname{RMSNorm}(H^{(24)}).
$$

**为什么需要？** lm_head 是一个线性分类器，对输入的尺度敏感。24 层堆叠后 $H^{(24)}$ 的数值尺度可能漂移（每层残差都在累积），不归一化直接分类，lm_head 看到的输入分布不稳定。final RMSNorm 把最后一层的输出拉回稳定尺度，与层内的 Pre-Norm 是同一个道理——**控制进入下一层/分类器的输入尺度**。

它没有可学习的偏置，只有逐维缩放 $\gamma$，与层内 RMSNorm 完全同一个算子。

## ④ lm_head：896 维变成 151936 个分数

分类器把最后一层的表示映射到词表：

$$
Z = H^{\text{final}} W_{\text{LM\_Head}}^T \in \mathbb{R}^{T \times 151936}, \qquad W_{\text{LM\_Head}} \in \mathbb{R}^{151936 \times 896}.
$$

$Z$ 的第 $i$ 行是位置 $i$ 的 logits——151936 个分数，对应词表里每个 token 的"下一个词候选程度"。softmax 后得到概率分布，采样产生下一个 token。

**为什么能 tied？** 输入 embedding 和输出 lm_head 共享同一张 $E$（272 MB 只存一份）。能共享的根本原因是**输入输出在同一个向量空间**：输入侧，$E$ 把 token 变成"这个词的表示"；输出侧，$W_{\text{LM\_Head}} = E$ 要求"预测一个词 = 和这个词的表示做内积"。一个 token 在输入侧是"被查找的向量"，在输出侧是"被匹配的目标"——语义一致，共享才合理。代价是模型不能独立学习输入/输出两侧的表示，这是小模型压参数量的妥协（详见 [[论文阅读/qwen/06-qwen模型文件与代码]] 的 `tie_word_embeddings`）。

## 一条 prompt 的完整旅程

把五个模块串起来，跟踪一个实际例子。输入"央行宣布降准"（4 个 token，$T=4$）：

```text title="data_flow.txt"
token ids:   [<bos>, 央行, 宣布, 降准]              ∈ ℤ[1,4]
    │ ① Embedding 查表
    ▼
H⁰           [4, 896]     每个 token 变成 896 维向量，尚无上下文
    │ ② 24 × DecoderLayer（每层形状不变）
    ▼
H²⁴          [4, 896]     "央行" 已融合 "宣布降准" 的上下文
    │ ③ final RMSNorm
    ▼
H^final      [4, 896]     尺度拉回稳定范围
    │ ④ lm_head
    ▼
logits       [4, 151936]  每个位置 151936 个候选分数
    │ softmax + 采样
    ▼
next token   预测第 5 个 token（如 "，" 或 "，央行宣布降准..." 的延续）
```

关键观察：**从 H⁰ 到 H²⁴，形状始终是 [4, 896]**。24 层做的全是"在 896 维空间里重塑表示"，唯一一次维度跳变发生在 lm_head（896 → 151936）。这就是 01 里"宽度由 $d_{\text{model}}$ 一锤定音"的具体形态。

## 参数量分布：钱花在哪

tied embeddings 下总参数约 4.94 亿（实测 494,032,768），分布：

| 模块 | 参数量 | 占比 | 说明 |
|:---|:---|:---|:---|
| Embedding / lm_head（共享） | 136,134,656 | 27.6% | 151936 × 896，输入输出共用一份 |
| 24 × DecoderLayer | 357,826,560 | 72.4% | 每层 14,909,440 |
| ├─ 其中 4 个注意力矩阵 | 1,833,984 | 12.3% | q/o 各 802,816，k/v 各 114,688 |
| ├─ 其中 3 个 MLP 矩阵 | 13,074,432 | 87.7% | gate/up/down 各 4,358,144 |
| **合计** | **493,961,216** | 100% | 约 4.94 亿 |

两个值得记住的比例：

- **MLP 占单层的 87.7%**——事实知识主要存在 SwiGLU 三个矩阵里，注意力矩阵反而小（尤其 GQA 下 k/v 只有 114,688）。这和"MLP 存知识、Attention 管路由"的分工一致。
- **Embedding 占全模型 27.6%**——152K 大词表的两面性：压缩率高，但输入输出两张表不共享的话要占 55%+，这正是 tie 的动机。

## 边界

- **"24 层"是 0.5B 的配置，不是架构定理**：层数和宽度是参数量预算下的权衡，更大模型改的是这两个数字，不是结构。
- **tied embeddings 只在小模型开启**：7B+ 通常关闭（lm_head 独立训练），这里展示的是 0.5B 的妥协，不是通用配置。
- **形状"全程不变"指主干维度**：注意力内部有临时的 (T, T) 矩阵、MLP 内部有 (T, 4864)，这些是子层内部的临时形状，不改变残差流。
