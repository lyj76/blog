# 论文阅读写作方法论：对齐 LoRA 的编排标准

> 这套标准不是常规知识。它从 [[论文阅读/lora/00-阅读地图]] 系列的反复杂改中提炼出来，回答一个问题：**什么样的技术笔记读起来"冷静、深入、编排完美"**。写任何论文阅读、技术专题系列前，先读这篇。

## 先定义：什么是"写得好"

技术笔记的读者不是来欣赏文采的，是来**建立因果链**的。写得好 = 读者读完能自己复述"为什么是这样"，而不是"记住了一堆结论"。

判断标准只有一条：**删掉任何一句话，推理链是否断裂**。能删掉而不影响理解的话，就是废话。

## 五个写作基因

### 1. 问题先行，断言式标题

标题应该是一句**论断**，不是目录条目。读者扫一眼就知道这节在证明什么。

| 目录式（差） | 断言式（好） |
|:---|:---|
| 每层 7 个权重矩阵：参数拓扑全景 | 为什么是 Decoder-Only |
| 端到端公式流：一个 Token 的完整旅程 | 满秩，不等于方向多 |
| 缩放因子 α/r 的物理意义 | 为什么不直接优化 BA |

每节开头先立问题，再给答案。公式是答案的一部分，不是开场白。

### 2. 数字锚点

每个抽象概念配一个**随手算得出来的具体例子**。抽象表述 + 具体数字 = 读者脑子里有了画面。

```
差：矩阵更新往往集中在少数方向。
好：σ=(10,1,0.1,0.01)，前两个方向带走 99.99% 的能量，截断到 r=2 几乎无损。
```

数字要嵌在散文里"边算边讲"，不是甩一张表格让读者自己算。

### 3. 边界意识（最稀缺的基因）

每篇必须有"什么结论归谁"的自觉：

- **实验观察 ≠ 定理**：经验概括要标注"这是经验观察，不是证明"；
- **贡献归属**：别把后续论文的改进记到原论文头上，别把标准数学结论记到某篇论文头上；
- **简化要声明**：为了讲清楚做的教学简化（如"24 层压成一层"），必须明说"真实结构不是这样"。

没有边界的文章会误导读者把假说当定理——这是知识库最贵的错误。

### 4. 冷静语气

陈述事实，不渲染。**无感叹号、无"最大""颠覆性""完整旅程"、无 emoji**。数字本身就是力度：

```
差：GQA 是现代 LLM 推理最大的显存赢家！
好：GQA 把 KV Cache 压缩为 MHA 的 1/7，即削减 85.7%。
```

### 5. 因果链叙述，不是罗列

用"→"把推理串起来，而不是逐条列结论。段落比例上**散文 ≈ 表格 7:3**——表格是结论的浓缩，不该是信息的唯一载体。

```
差：注意力能并行。注意力能长距离直连。注意力是 O(T²)。
好：这条链是通的：能量集中 → 截断小奇异值 → 最佳 rank-r 近似。而这个近似本身就能写成 BA。
```

## 结构编排模板

### 粒度递进：整体 → 架构 → 单层 → 内部

一篇主线文的天然粒度顺序，**不要跳级**：

```
1. 整体问题（为什么是这种方案）
2. 因果链（一条性质给出两个收益）
3. 端到端链路（黑盒视角：输入到输出）
4. 架构全景（展开黑盒：模块组成、形状流转）
5. 单层内部（聚焦一层：7 个矩阵逐个摆开）
6. 功能分化（层间分工）
7. 边界（收束）
```

跳级是读起来"不顺"的头号原因——从端到端链路直接钻进单层矩阵，中间缺了架构层，读者会迷路。

### 系列编排：主文 + 专题篇

系列不要一篇塞满。**主文建因果链，专题篇承载证明**：

```
00-阅读地图    索引 + 符号系统 + 依赖关系
01-主线        问题 → 方案 → 边界（主文，自含因果链）
02-数学引擎    主文引用的定理/推导放这里（SVD、四算子拆解）
03-……          其他专题（参数、训练、推理、代码）
```

篇与篇之间必须有**承接**（开头"承接 01：……"）和**索引**（结尾"详见 02/03"），形成闭环。

### 每篇的结构骨架

```
# 标题（论断式）

> 承接 [[上一篇]]：…… 本篇回答什么问题。索引见 [[00-阅读地图]]。

## 问题小节
（每节：立问题 → 给公式 → 数字锚点 → 表格浓缩结论）

## 边界
（经验观察 vs 定理、贡献归属、简化的代价）

详见 [[下一篇]]。
```

## 反模式清单

写作时对照，出现任何一条就要重写：

- [ ] 标题是名词短语而非论断
- [ ] 段落比表格多不了多少（散文:表格 < 6:4）
- [ ] 有感叹号、"最大/颠覆性/完整旅程"等渲染词
- [ ] 教学简化没有声明（如把 24 层压成单个 W_MLP 还不说明）
- [ ] 经验观察写成定理（"浅层管语法"直接当结论引用）
- [ ] 有 `:::note`/`:::tip`/`> [!NOTE]` 等 admonition 块（LoRA 系列不用，正文用普通段落）
- [ ] 中英混写术语（"14 heads × 64 dim"→ 应为 $h_q \times d_h$）
- [ ] 篇内零引用（中段应有 `见 [[XX]]` 这类链接把结论挂到相关篇目——注意示例要写在代码块里，否则会被 wiki 插件误解析）

## 发布前检查清单

- [ ] 标题论断式、承接/索引/详见闭合
- [ ] 每个公式检查符号一致性（$d_{\text{model}}$ 全文同义）
- [ ] 表格数据可复算（参数量、显存、百分比随手验算）
- [ ] 散文:表格 ≥ 7:3
- [ ] 跑 `WIKI_LINK_STRICT=true pnpm build` 确认零断链
- [ ] 通读一遍：删掉任何一句话，推理链是否断裂
