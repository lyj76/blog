# Python 装饰器与上下文管理器：@torch.no_grad / with

Python 有两种「给代码包一层」的语法：装饰器 `@` 包函数，`with` 包代码块。两者都能在原逻辑前后插入额外行为，是看懂训练/推理代码的关键。

## 1. 装饰器 `@` 的本质：函数套函数

```python title="decorator-essence.py"
def log(func):
    def wrapper(*args, **kwargs):
        print("调用前")
        result = func(*args, **kwargs)
        print("调用后")
        return result
    return wrapper

@log
def f(x):
    return x + 1

f(3)    # 打印「调用前」→ 返回 4 → 打印「调用后」
```

- `@log` 是语法糖，等价于 `f = log(f)`：把 `f` 传给 `log`，返回 `wrapper`
- 调用 `f(3)` 实际调的是 `wrapper(3)`，wrapper 内部再调原函数
- `wrapper` 用 `*args, **kwargs` 接住任意参数，原样转发给 `func`

::::note
**C++ 类比**：装饰器像 C++ 的「包装类」。外层对象持有内层函数指针，调用时先做自己的事再转发。Python 用函数嵌套实现，不用建类。
::::

## 2. `@torch.no_grad()`：推理时关闭梯度

```python title="no-grad-decorator.py"
@torch.no_grad()
def generate(model, prompt):
    outputs = model.generate(prompt)
    return outputs
```

- `torch.no_grad()` 返回一个装饰器，套在函数外
- 被装饰的函数内，所有张量运算**不记录计算图**
- 效果：省显存、省内存、速度快；推理必须用，训练（要 backward）不能用

::::warning
**训练和推理的区别**：训练要 `loss.backward()` 算梯度，必须保留计算图；推理只前向，留着图纯浪费显存。`@torch.no_grad()` 就是告诉 PyTorch「这段代码不用留图」。
::::

## 3. `with` 语句：上下文管理器

```python title="with-example.py"
with open("data.txt") as f:
    text = f.read()
# 离开 with 块自动调 f.close()，即使中间抛异常也会关
```

- `with obj as x:` 进入时调 `obj.__enter__()`，返回值赋给 `x`
- 离开代码块（正常或异常）时调 `obj.__exit__()`，做清理
- 文件、锁、数据库连接都用这套，保证资源释放

::::note
**C++ 类比**：`with` 是 RAII 的 Python 版本。C++ 里「构造即获取、析构即释放」靠栈对象生命周期；Python 没有析构保证，用 `with` 显式划定释放点。
::::

## 4. `with torch.no_grad():` 的用法

```python title="no-grad-with.py"
# 形态一：装饰器，整个函数都不留图
@torch.no_grad()
def evaluate(model):
    ...

# 形态二：with 块，只这一段不留图
def run(model):
    model.train()
    loss = model(...).loss      # 训练：留图
    loss.backward()

    with torch.no_grad():       # 推理：不留图
        out = model.generate(...)
    return out
```

- 同一个 `torch.no_grad()` 有两种用法：装饰器包函数、`with` 包代码块
- 装饰器适合「整个函数都是推理」；`with` 适合「函数里只有一段是推理」
- 两者效果完全一样，选哪个看代码结构

## 5. `functools.wraps`：保留原函数信息

```python title="wraps-example.py"
from functools import wraps

def log(func):
    @wraps(func)                # 让 wrapper 保留原函数的名字、文档
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper
```

- 不加 `@wraps(func)`，被装饰的函数 `__name__` 会变成 `wrapper`
- 加了之后，`f.__name__` 还是原来的名字，调试和反射更友好
- 自己写装饰器时建议加上，库里的装饰器（如 `@torch.no_grad()`）内部已处理

## 小结

| 语法 | 作用 |
| --- | --- |
| `@deco` | 装饰器，`f = deco(f)` 的语法糖 |
| `@torch.no_grad()` | 函数内不留计算图，推理专用 |
| `with obj as x:` | 进入调 `__enter__`，退出调 `__exit__` |
| `with torch.no_grad():` | 代码块内不留图，同装饰器效果 |
| `@functools.wraps(func)` | 保留被装饰函数的元信息 |
