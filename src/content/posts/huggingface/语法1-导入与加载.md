# HuggingFace 语法①：import 与模型/分词器加载

从 LoRA 训练脚本开头总结，搞定「怎么把模型和分词器加载进来」。

## 1. 导入：`from transformers import ...`

```python title="import-example.py"
from transformers import AutoTokenizer, AutoModelForCausalLM
from datasets import load_dataset
import torch
```

- `from 包 import 名字`：从第三方包导入类/函数，导入后直接 `AutoTokenizer` 使用
- `transformers` 是 HuggingFace 的核心包：`AutoTokenizer` 管文本↔id，`AutoModelForCausalLM` 管模型
- `datasets` 是数据包：`load_dataset` 加载公开数据集

::::note
**`Auto` 前缀的含义**：`AutoTokenizer` 会根据模型路径自动选择正确的分词器实现（不同模型用不同分词器，你不用手动指定）。同理 `AutoModelForCausalLM` 自动匹配模型架构。名字里的 `ForCausalLM` 表示「用于因果语言建模」（自回归生成），即 Qwen / Llama 这类模型。
::::

## 2. 加载分词器：`AutoTokenizer.from_pretrained()`

```python title="tokenizer-load.py"
tokenizer = AutoTokenizer.from_pretrained(MODEL_PATH)
```

- `from_pretrained` 是**类方法**（不用 new 实例，直接类名调用），从**本地路径**或 **HuggingFace 在线仓库 id** 加载
- `MODEL_PATH` 传本地文件夹路径（如 `"./Qwen2.5-0.5B-Instruct"`）时，读取该目录里的 `tokenizer_config.json` / `vocab.json` 等文件

**pad_token 兜底写法**（几乎每个脚本都有）：

```python title="pad-token-fallback.py"
if tokenizer.pad_token_id is None:
    tokenizer.pad_token_id = tokenizer.eos_token_id
```

- `tokenizer.pad_token_id`：填充（padding）用的特殊 token id；有些模型没定义 pad_token，值为 `None`
- 训练要 padding 成等长批次，所以把结束符 `eos_token_id` 当填充符用

## 3. 加载模型：`AutoModelForCausalLM.from_pretrained()`

```python title="model-load.py"
dtype = torch.bfloat16 if device == "cuda" else torch.float32
model = AutoModelForCausalLM.from_pretrained(MODEL_PATH, torch_dtype=dtype)
```

**`torch_dtype=...` 关键字参数**：指定模型权重的精度：

| dtype | 用途 |
| --- | --- |
| `torch.bfloat16` | GPU 训练常用，省显存、够精度 |
| `torch.float32` | CPU 或保险起见 |
| `torch.float16` | 部分 GPU 优化 |

`torch.bfloat16 if device == "cuda" else torch.float32` 是**条件表达式**（三目运算）：条件成立取前者，否则取后者。

## 4. 移动到设备：`model.to(device)`

```python title="to-device.py"
model.to("cuda")    # 模型所有参数搬去 GPU
```

`model.to(device)` 把模型**所有参数和缓冲区**移到指定设备，是 `nn.Module` 自带方法。

::::warning
**注入 LoRA 之后再 `.to()`**：如果先 `model.to("cuda")` 再注入 LoRA，新创建的 A/B 矩阵默认在 CPU，前向时和 GPU 上的原层设备不一致直接报错。所以顺序是：**加载 → 注入 → 统一 to(device)**。
::::

## 5. 加载数据集：`load_dataset()`

```python title="dataset-load.py"
from datasets import load_dataset

stream = load_dataset("hugcyp/LCSTS", split="train", streaming=True)
```

从 HuggingFace 仓库加载数据集：`split` 指定划分，`streaming=True` 流式加载。**详细用法（split / 流式 / 截断 / 转 Dataset）见 [语法⑤：load_dataset 数据集加载](./语法5-load_dataset数据集加载/)**。

## 6. 脚本入口：`if __name__ == "__main__"`

```python title="main-guard.py"
if __name__ == "__main__":
    main()
```

- 直接运行 `python train.py` 时 `__name__` 为 `"__main__"`，执行 `main()`
- 被 `import` 时不执行——保证「运行脚本才跑，导入模块只拿函数」

## 小结

| 语法 | 作用 |
| --- | --- |
| `from transformers import AutoTokenizer, AutoModelForCausalLM` | 导入加载器 |
| `AutoTokenizer.from_pretrained(path)` | 加载分词器 |
| `tokenizer.pad_token_id is None` → 用 eos 兜底 | 补齐填充符 |
| `AutoModelForCausalLM.from_pretrained(path, torch_dtype=dtype)` | 加载模型并指定精度 |
| `model.to("cuda")` | 参数搬设备 |
| `load_dataset("仓库", split="train", streaming=True)` | 流式加载数据集 |
