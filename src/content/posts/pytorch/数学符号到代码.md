# PyTorch 数学符号到代码：矩阵运算直觉与转置桥

读论文公式头晕、写代码要猜形状、`model(x)` 和手写 `A@B` 分不清……这些问题的根源是同一个，但**答案比想象中简单**：转置只出现在**一个地方**——把权重作用到数据（forward）时。别的所有矩阵操作（组合、合并、更新权重）都是普通 `@`，永无转置。

> 归属：**PyTorch · `torch`** —— 矩阵运算直觉，连接数学记号与张量代码。

## 概念本体：两个世界，一个转置

矩阵运算分两个"世界"，转置只在**它们的交界处出现一次**：

**世界 A：权重世界（矩阵当映射）**
- 所有权重按数学约定存储：$W \in \mathbb{R}^{out \times in}$——`(out, in)`
- 在这个世界里**组合、合并、更新权重**：普通 `@`，**永远不用转置**

```
W = B @ A     # 合并两个权重：普通 @ ✓（B (out,r)、A (r,in) 维度自然接上）
```

**世界 B：数据世界（张量当行批次）**
- 数据是**行**：`x` 形状 `[batch, features]`——每行一个样本

**唯一交界：把权重作用到数据**（forward 那一步）。在这里，数据是行、权重是列约定——`in` 维要对齐，所以**转置一次**：

```
数学：  y = W·x          （W 左乘列向量）
代码：  y = x @ W.T      （W.T 右乘行数据） ← 唯一的转置
```

```
权重世界（映射，普通 @）                数据世界（行批次）
  W (out,in), B (out,r), A (r,in)         x [batch, in]
        │                                    │
        └── W = B @ A（组合，无转置）──────────┘
                    │
        y = x @ W.T ← 唯一的转置：把映射作用到行数据
```

**判定一句话**：
- 你在**摆弄权重**（组合、合并、更新）→ 普通 `@`，别想转置
- 你在**把权重作用到数据** → 这里才需要 `.T`

## nn.Linear：那个唯一的转置藏在这里

`nn.Linear(in_features, out_features)` 创建的权重是 `(out, in)`（数学约定）：

```python title="linear-shape.py"
import torch.nn as nn

layer = nn.Linear(4, 3)          # 输入 4 维，输出 3 维
print(layer.weight.shape)        # torch.Size([3, 4])  ← (out, in)
print(layer.bias.shape)          # torch.Size([3])     ← (out,)
```

**forward 内部**（`model(x)`）做的就是"把权重作用到数据"——唯一需要转置的地方：

```
weight [3, 4]：每一行是一个输出神经元的系数
  ┌  1   0  -1   0 ┐   ← 输出 1 的系数
  │  0   1   0  -1 │   ← 输出 2 的系数
  └  1   1   0   0 ┘   ← 输出 3 的系数

x [2, 4]：每一行是一个样本
  ┌  1   0   2   1 ┐
  └  0   1   1   0 ┘
```

`x @ weight.T` 手算样本 1（转置后逐列点积 = 权重每行 × 样本）：

```
输出 1 = [1,0,2,1]·[1,0,-1,0] = 1·1 + 0·0 + 2·(-1) + 1·0 = -1
输出 2 = [1,0,2,1]·[0,1,0,-1] = 0 + 0 + 0 + (-1)      = -1
输出 3 = [1,0,2,1]·[1,1,0,0]  = 1 + 0 + 0 + 0         =  1
样本 1 输出 = [-1, -1, 1]

形状：x [2,4] @ weight.T [4,3] → [2,3] + bias [3] → [2,3] ✓
```

```python title="linear-forward.py"
out = layer(x)
# 完全等价：out = x @ layer.weight.T + layer.bias
```

## 权重组合不动转置（正面回答"为什么只有 forward 需要"）

你观察完全正确：**只有 forward 需要 `.T`，其他操作一律普通 `@`**。原因就是两个世界的边界——摆弄权重在"权重世界"，维度约定自洽，转置无从谈起：

| 操作 | 世界 | 代码 | 转置？ |
| --- | --- | --- | --- |
| 合并权重 $W = BA$ | A（映射组合） | `W = B @ A` | **否** |
| 更新权重 $W \gets W + \Delta$ | A（数值更新） | `W.data += dW` | **否** |
| 组合 $AB$ | A（映射组合） | `A @ B` | **否** |
| 把权重作用到数据 $y = Wx$ | A→B 交界 | `x @ W.T` | **是，唯一一次** |

**为什么合并不用转置**：$B$ 是 `(out, r)`、$A$ 是 `(r, in)`——它们是"映射"约定，`@` 要求"左边末维 = 右边倒数第二维"：`r` 对上 `r`，**自然接合**，不需要转置。转置只在该把"映射"喂给"行数据"时才冒出来。

## model(x) vs 手写 A@B：不是二选一

**`model(x)` 内部就是 `x @ W.T + b`**——用哪个完全等价。区别只在你要什么：

| 用 `model(x)` | 手写 `A @ B` |
| --- | --- |
| 要整层结果，不关心中间量 | 要**中间结果**（如 LoRA 先取 `x @ A.T`） |
| 参数由模块统一管理 | 多分支计算、手动合并权重后自算 |
| 代码干净 | 扮演 forward |

::::tip
**判断准则**：只要"手写 = 模块 forward 的同一个运算"，就安全。合并权重后没有现成层，必须手写——那时你在**扮演 forward**，自然要写那个唯一的 `.T`。
::::

## 论文公式 → 代码：三步法（以 LoRA 走一遍）

论文 LoRA 前向：$h = W_0 x + B A x$

**第一步：标形状**

| 符号 | 形状 | 含义 |
| --- | --- | --- |
| $x$ | `[batch, in]` | 输入（数据世界，行） |
| $W_0$ | `(out, in)` | 原始权重（权重世界） |
| $A$ | `(r, in)` | 降维权重 |
| $B$ | `(out, r)` | 升维权重 |
| $h$ | `[batch, out]` | 输出（数据世界） |

**第二步：分清每个运算在哪个世界**

```
权重世界（映射组合）→ 普通 @，无转置：
  合并：W_new = W₀ + B @ A          ← B (out,r) @ A (r,in)，自然接合

数据世界（作用到 x）→ 唯一的转置：
  W₀x   →  x @ W₀.T                 ← 把权重作用到数据，转置
  BAx   →  (x @ A.T) @ B.T          ← 链式：先 A 后 B，各转置一次
```

**第三步：查维度**

```
x [batch, in] @ W₀.T [in, out]     → [batch, out]  ✓
x [batch, in] @ A.T  [in, r]       → [batch, r]    ✓
(x@A.T) [batch, r] @ B.T [r, out]  → [batch, out]  ✓
```

两个分支都是 `[batch, out]`，可相加：

```python title="lora-both.py"
# 训练时（每次前向都要作用到数据）：
h = x @ W0.T + (x @ A.T) @ B.T

# 合并权重（一次性，权重世界，无转置）：
W_new = W0 + B @ A
```

**同一个 LoRA，两种形态**——正是"两个世界"的活例子：合并权重在权重世界（`B @ A` 无转置），前向把合并结果作用到数据（`x @ W_new.T` 有转置）。

**三步法通用**：标形状 → 分世界（组合=普通 @ / 作用到数据=转置）→ 查维度。

## 竖向量执念：放下它

你偏好"竖向量"（列向量）——数学里确实如此。但 PyTorch 的现实：

```python title="column-vector.py"
v = torch.tensor([1.0, 2.0, 3.0])   # 形状 [3]：一维，没有行/列之分
v.unsqueeze(1)                       # [[1],[2],[3]] 形状 [3,1] ← 真列向量
v.unsqueeze(0)                       # [[1,2,3]]   形状 [1,3] ← 真行向量
```

**一维张量 `[d]` 既不是行也不是列**。要参与矩阵运算才明确方向：列向量 `unsqueeze(1)`，行向量 `unsqueeze(0)`。

**训练数据生态约定是"行"**：`[batch, features]`——遍布 DataLoader、nn.Linear、损失函数，别跟它对着干。

## 速查表

| 数学 | PyTorch | 转置？ |
| --- | --- | --- |
| $y = Wx$（作用到数据） | `x @ W.T` | **是**（唯一的） |
| $W = BA$（组合权重） | `W = B @ A` | 否 |
| $W^T$ | `W.T` | 转置本身 |
| $AB$（两个映射相乘） | `A @ B` | 否 |
| $\langle x, y \rangle$ | `x @ y` | 一维内积 |
| $\sum_i w_i x_i$ | `(x * w).sum(dim=-1)` 或 `x @ w` | 等价 |
| 逐元素乘 | `A * B` | **不是**矩阵乘！ |
| $\operatorname{softmax}(z)$ | `z.softmax(dim=-1)` | 沿最后一维 |

::::warning
**`*` 和 `@` 是天壤之别**：`A * B` 是逐元素乘（形状相同可广播），`A @ B` 是矩阵乘（维度匹配）。论文里的 $AB$ 一定是 `@`（见 [[张量广播与组合]]）。
::::

## 小结

| 知识 | 要点 |
| --- | --- |
| 两个世界 | 权重世界（映射，普通 @） + 数据世界（行批次） |
| 唯一转置 | 只在"把权重作用到数据"（forward）：`x @ W.T` |
| 权重组合 | `W = B @ A` 普通 @，**永无转置** |
| Linear | weight `(out, in)`，forward 内部 = `x @ W.T + b` |
| model(x) vs 手写 | 等价；手写用于中间结果 / 合并权重 |
| 三步法 | 标形状 → 分世界（组合普通 @ / 作用数据转置）→ 查维度 |
| `*` vs `@` | 逐元素乘 vs 矩阵乘，别混 |
