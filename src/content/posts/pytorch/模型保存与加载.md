# PyTorch 模型保存与加载：state_dict / torch.save / load_state_dict

训练完的模型怎么存？预训练权重怎么加载？这篇把 `state_dict`、`torch.save`、`load_state_dict` 三件事讲清。

> 归属：**PyTorch · `torch`** —— 保存与加载属于训练引擎 PyTorch。

## 1. state_dict 是什么

```python title="state-dict-example.py"
import torch
import torch.nn as nn

model = nn.Linear(3, 2)
sd = model.state_dict()
print(type(sd))   # collections.OrderedDict
print(sd.keys())  # odict_keys(['weight', 'bias'])
print(sd['weight'].shape)   # torch.Size([2, 3])
```

- `state_dict()` 返回一个 `OrderedDict`：**键是参数名，值是张量**
- 包含所有 `nn.Parameter` 与 buffer（如 BatchNorm 的 running_mean）
- 只存数据，不存计算图（`.grad_fn` 为 `None`，`.grad` 不保留）

::::note
**参数名的命名规则**：嵌套模块用点分路径，如 `encoder.layers.0.self_attn.q_proj.weight`。这个路径与 `named_parameters()` 返回的名字一致，加载时按名字匹配。
::::

## 2. torch.save：两种保存方式

```python title="save-methods.py"
# 方式 1：只存 state_dict（推荐）
torch.save(model.state_dict(), "model.pt")

# 方式 2：存整个 model 对象
torch.save(model, "model_full.pt")
```

| 方式 | 内容 | 优点 | 缺点 |
| --- | --- | --- | --- |
| `torch.save(model.state_dict(), path)` | 参数字典 | 跨环境、跨版本兼容 | 加载时需先建模型实例 |
| `torch.save(model, path)` | 整个对象（含类定义） | 一行加载 | 依赖 pickle，**跨目录/版本易崩** |

::::important
**永远用方式 1**：保存 `state_dict` 是官方推荐做法。方式 2 用 pickle 序列化整个对象，加载时必须能 import 到完全相同的类定义，跨项目、跨 PyTorch 版本经常报错。
::::

## 3. load_state_dict：加载与校验

```python title="load-example.py"
model = MyModel()   # 先建一个空模型实例
state = torch.load("model.pt", map_location="cpu")   # 加载字典
model.load_state_dict(state)   # 默认 strict=True
```

- `load_state_dict(sd)` 把 `sd` 里的张量**按名字复制**到模型对应参数
- `map_location="cpu"`：把存在 GPU 上的权重加载到 CPU（再 `.to(device)` 搬走）
- 复制的是数值，不是引用（模型参数对象本身不变）

## 4. strict=True：缺键/多键报错

```python title="strict-example.py"
model = MyModel()
state = torch.load("pretrained.pt")

# strict=True（默认）：键必须完全匹配
model.load_state_dict(state)
# RuntimeError: Missing key(s): "classifier.weight"
# Unexpected key(s): "head.weight"

# strict=False：只加载匹配的键，忽略不匹配的
model.load_state_dict(state, strict=False)
```

- `strict=True`：模型与 state_dict 的键**必须完全一致**，缺一个或多一个都报错
- `strict=False`：只加载两边都有的键，缺的保持初始化值，多的忽略
- 报错信息会明确列出 `Missing key(s)` 与 `Unexpected key(s)`

::::warning
**`strict=False` 的风险**：它会**静默**忽略不匹配的键。如果你以为加载了某层，实际没加载（键名拼错），模型会带着随机初始化的权重训练，很难发现。只在迁移学习、明确知道哪些层要跳过时用。
::::

## 5. 迁移学习套路

```python title="transfer-learning.py"
# 1. 加载预训练模型
model = MyModel()
state = torch.load("pretrained.pt", map_location="cpu")
model.load_state_dict(state, strict=False)   # 容忍分类头不匹配

# 2. 替换分类头（新任务类别数不同）
model.classifier = nn.Linear(in_features, num_new_classes)

# 3. 冻结骨干（可选）
for name, param in model.named_parameters():
    if not name.startswith("classifier"):
        param.requires_grad = False

# 4. 只训练新分类头
optimizer = AdamW([p for p in model.parameters() if p.requires_grad], lr=1e-3)
```

- 预训练权重里没有新分类头 → `strict=False` 跳过它
- 替换后的分类头是随机初始化的，需要训练
- 冻结骨干 + 只训分类头是迁移学习最简形式

## 6. 与 HF save_pretrained 的对应

```python title="hf-correspondence.py"
# 原生 PyTorch
torch.save(model.state_dict(), "model.pt")
model.load_state_dict(torch.load("model.pt"))

# HuggingFace Transformers
model.save_pretrained("./my_model")        # 存到目录（含 config.json + 权重）
model = AutoModel.from_pretrained("./my_model")   # 从目录加载
```

- HF 的 `save_pretrained` 本质还是存 `state_dict`，只是多了 `config.json`（模型结构配置）和分片权重文件
- 原生 `torch.save` 只存权重，模型结构要靠你**自己建实例**；HF 用 `from_pretrained` 自动读 config 建模型

::::tip
**何时用哪个**：自己手搓的模型用 `torch.save` + `load_state_dict`；用 HF 模型库就用 `save_pretrained` / `from_pretrained`，省心。
::::

## 小结

| 语法 | 作用 / 返回 |
| --- | --- |
| `model.state_dict()` | 返回 OrderedDict（参数名 → 张量） |
| `torch.save(model.state_dict(), path)` | 保存权重（推荐） |
| `torch.save(model, path)` | 保存整个对象（不推荐） |
| `model.load_state_dict(sd)` | 加载权重，默认 `strict=True` |
| `load_state_dict(sd, strict=False)` | 容忍键不匹配（迁移学习用） |
| `torch.load(path, map_location="cpu")` | 加载到 CPU（再搬设备） |
| `model.save_pretrained(dir)` | HF 等价保存（含 config） |
