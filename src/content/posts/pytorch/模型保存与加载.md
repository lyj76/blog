# PyTorch 模型保存与加载：state_dict / torch.save / load_state_dict

训练完的模型怎么存？下次怎么读回来？这篇用一个模型贯穿保存 → 加载 → 校验 → 迁移的全过程。

> 归属：**PyTorch · `torch`** —— 保存与加载属于训练引擎 PyTorch。

## 1. 保存的本质：把参数张量打包成字典

一个模型 = 结构 + 一堆参数张量。保存的本质就是**把这堆张量打包**——`state_dict()` 就是那个打包结果：

```python title="state-dict-example.py"
import torch
import torch.nn as nn

model = nn.Sequential(nn.Linear(10, 32), nn.ReLU(), nn.Linear(32, 2))

sd = model.state_dict()
type(sd)              # collections.OrderedDict
sd.keys()             # odict_keys(['0.weight', '0.bias', '2.weight', '2.bias'])
sd['0.weight'].shape  # torch.Size([32, 10])
```

- `state_dict()` 返回 `OrderedDict`：**键 = 参数名，值 = 参数张量**
- 键名就是模块路径：`0.weight` = 第 0 层的权重、`2.bias` = 第 2 层的偏置
- 只存**数据**（张量值），不存结构、不存计算图（`.grad` 不保留）

::::note
**命名规则**：嵌套模块用点分路径，如 `encoder.layers.0.self_attn.q_proj.weight`。键名与 `named_parameters()` 一致，**加载时按名字匹配**。
::::

## 2. 怎么存：只存权重，别存整个对象

```python title="save-methods.py"
# 方式 1（推荐）：只存权重字典
torch.save(model.state_dict(), "model.pt")

# 方式 2（不推荐）：把整个模型对象序列化
torch.save(model, "model_full.pt")
```

| 方式 | 存了什么 | 缺点 |
| --- | --- | --- |
| `torch.save(model.state_dict(), path)` | 参数张量字典 | 加载时要自己重建同构模型 |
| `torch.save(model, path)` | 整个对象（含类定义） | 依赖 pickle，跨目录/跨版本**经常崩** |

::::important
**永远用方式 1**：方式 2 用 pickle 把整个 Python 对象（含类引用）序列化，加载时必须能 `import` 到**完全相同的类定义**——换个项目、升级 PyTorch 就报错。方式 1 只存张量，任何环境都能读。
::::

## 3. 怎么读：先重建同构模型，再按名字填进去

保存只存了权重，**结构要靠你自己重建**——加载是两步：

```python title="load-example.py"
# ① 重建和保存时一模一样的模型结构（关键！）
model = nn.Sequential(nn.Linear(10, 32), nn.ReLU(), nn.Linear(32, 2))

# ② 把权重填进去
state = torch.load("model.pt", map_location="cpu")   # 读出字典
model.load_state_dict(state)                          # 按名字复制张量
```

- `load_state_dict(sd)` 把 `sd` 里的张量**按名字**复制到模型的对应参数——名字对不上就报错（下一节）
- `map_location="cpu"`：权重本来在 GPU 上时，先读到 CPU 再 `.to(device)` 搬——避免内存/显存不匹配
- **结构必须一致**：保存的是 `nn.Sequential(Linear(10,32), ...)`，加载时也必须一模一样——这是方式 1 的代价，也是它的安全所在

## 4. 键不匹配怎么办：strict 校验

`load_state_dict` 默认 `strict=True`——**模型和字典的键必须完全一致**：

```python title="strict-example.py"
model = nn.Sequential(nn.Linear(10, 32), nn.ReLU(), nn.Linear(32, 2))
model.load_state_dict(torch.load("pretrained.pt"))
# RuntimeError: Missing key(s): "2.weight"、Unexpected key(s): "3.weight"
# ↑ 结构对不上时，报错明确列出缺了谁、多了谁
```

- `strict=True`（默认）：缺一个键或多一个键都**直接报错**——保护你不"假装加载成功"
- `strict=False`：只加载两边都有的键，缺的保持初始化值、多的忽略——**静默**的
- 报错信息永远会列出 `Missing key(s)` 和 `Unexpected key(s)`，照着改结构即可

::::warning
**`strict=False` 的风险**：它静默忽略不匹配的键。键名拼错时你以为加载了、实际没加载，模型带着随机权重训练，很难发现。**只在明确知道要跳过某些层时用**（下一节就是）。
::::

## 5. 迁移学习：strict=False 的正确用法

换分类头（新任务类别数不同）时，预训练权重里**没有新分类头**，必须容忍键不匹配：

```python title="transfer-learning.py"
# ① 加载预训练权重，跳过不匹配的层
model = nn.Sequential(nn.Linear(10, 32), nn.ReLU(), nn.Linear(32, 2))
state = torch.load("pretrained.pt", map_location="cpu")
model.load_state_dict(state, strict=False)   # 结构不同的层保持随机初始化

# ② 替换分类头（新任务类别数不同）
model[2] = nn.Linear(32, 5)                  # 换成 5 分类

# ③ 冻结骨干，只训练新头
for name, param in model.named_parameters():
    if "2." not in name:                     # 只留分类头的参数
        param.requires_grad = False

optimizer = AdamW([p for p in model.parameters() if p.requires_grad], lr=1e-3)
```

- **为什么必须 strict=False**：新分类头在预训练权重里不存在，`strict=True` 会因缺键报错
- 替换后的新头是随机初始化的，所以**冻结骨干 + 只训新头**——骨干能力保留，新头从零学
- （冻结的做法见「优化器内部」篇的 LoRA 场景）

## 小结

| 语法 | 作用 / 返回 |
| --- | --- |
| `model.state_dict()` | 参数打包成 OrderedDict（名字 → 张量） |
| `torch.save(model.state_dict(), path)` | 只存权重（推荐，任何环境可读） |
| `torch.save(model, path)` | 存整个对象（不推荐，pickle 易崩） |
| `torch.load(path, map_location="cpu")` | 读出字典（先到 CPU） |
| `model.load_state_dict(sd)` | 按名字复制张量，默认 `strict=True` |
| `load_state_dict(sd, strict=False)` | 容忍键不匹配（迁移学习换头时用） |

（HuggingFace 模型的 `save_pretrained` / `from_pretrained` 是这套机制的封装——自动存/读结构配置，见「auto 机制与模型加载」篇。）
