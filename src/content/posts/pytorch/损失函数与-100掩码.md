# PyTorch 损失函数与 -100 掩码：CrossEntropyLoss

LLM 训练里 labels 总是塞一堆 `-100`，这个约定从哪来？为什么直接传 logits 而不是先 softmax？这篇把 `CrossEntropyLoss` 讲透。

> 归属：**PyTorch · `torch.nn`** —— 损失函数（`CrossEntropyLoss` 属于 `torch.nn`）。

## 1. CrossEntropyLoss 的定义

```python title="ce-example.py"
import torch
import torch.nn as nn

logits = torch.tensor([[2.0, 1.0, 0.1]])   # [1, 3] —— 3 个类的原始分
target = torch.tensor([0])                  # [1] —— 正确类别索引
loss = nn.CrossEntropyLoss()(logits, target)   # 标量张量
```

- 内部 = `LogSoftmax` + `NLLLoss`：先对 logits 取 log 概率，再取正确类的负 log 概率
- 输入 `logits` 形状 `[batch, num_classes]`，`target` 形状 `[batch]`（类索引）
- 返回标量（默认对所有 batch 取平均）

::::important
**别再手动 softmax**：`CrossEntropyLoss` 内部已经做了 `log(softmax(...))`。如果你先 `softmax(logits)` 再传进去，等于做了两次 softmax，结果完全错误。直接传原始 logits。
::::

## 2. ignore_index=-100：-100 约定的真正来源

```python title="ignore-index-example.py"
logits = torch.tensor([[2.0, 1.0, 0.1], [0.5, 2.5, 0.3]])
target = torch.tensor([0, -100])   # 第 2 个样本不参与损失
loss = nn.CrossEntropyLoss(ignore_index=-100)(logits, target)
# 等价于只用第 1 个样本算 loss
```

- `ignore_index` 默认值就是 `-100`，指定某个标签值**不参与损失计算**
- 这就是 LLM 训练里 labels 塞 `-100` 的**真正来源**：padding 位置、prompt 位置都填 `-100`，让模型只对真正要生成的 token 算损失
- 不显式传 `ignore_index=-100` 也能用，因为这就是默认值

::::note
**为什么是 -100 而不是 0 或 -1**：0 是合法类别索引（词表第 0 个 token），-1 也可能被某些场景当索引用。-100 是个不会与任何合法类别冲突的"哨兵值"，PyTorch 选了它做默认。
::::

## 3. softmax vs log_softmax 数值稳定性

```python title="softmax-stability.py"
# 手写 softmax（不推荐）
def softmax(x):
    return x.exp() / x.exp().sum(dim=-1, keepdim=True)

# log_softmax（数值稳定版）
def log_softmax(x):
    x = x - x.max(dim=-1, keepdim=True).values   # 减最大值防溢出
    return x - x.exp().sum(dim=-1, keepdim=True).log()
```

- `softmax` 直接 `exp` 再归一：大 logits 时 `exp` 爆到 inf（上溢）
- `log_softmax` 先减最大值再算：等价结果但数值稳定
- `CrossEntropyLoss` 内部用的是稳定的 `log_softmax`，所以直接传大 logits 也不会炸

::::warning
**手算 loss 别用 `log(softmax(x))`**：先 softmax 再 log 会损失精度（小概率 → 0 → log(0) = -inf）。要么直接用 `CrossEntropyLoss`，要么用 `F.log_softmax` + `F.nll_loss`。
::::

## 4. LLM 场景：(batch, seq, vocab) 形状

```python title="llm-loss-shape.py"
# logits: [batch, seq, vocab]
# labels: [batch, seq]
logits = outputs.logits              # [4, 256, 50257]
labels = batch["labels"]             # [4, 256]

# 方法 1：reshape 后用 CrossEntropyLoss
loss = nn.CrossEntropyLoss(ignore_index=-100)(
    logits.view(-1, logits.size(-1)),   # [1024, 50257]
    labels.view(-1)                      # [1024]
)

# 方法 2：模型内部已算（HF 模型传 labels 自动算）
outputs = model(input_ids=input_ids, labels=labels)
loss = outputs.loss   # 标量
```

- `CrossEntropyLoss` 要求 `logits` 末维是类别数，前面任意
- LLM 输出 `[batch, seq, vocab]`，需 `view(-1, vocab)` 摊平前两维，labels 同步 `view(-1)`
- HF 模型内部就是按方法 2 算的：传 `labels` 进 `forward`，返回 `outputs.loss`

## 5. -100 位置不参与损失的机制

```python title="mask-mechanism.py"
labels = torch.tensor([10, 20, -100, 30, -100])
# CrossEntropyLoss 内部：
# 1. 对每个位置算 log_softmax + nll
# 2. mask = labels != -100   → [T, T, F, T, F]
# 3. 只对 mask=True 的位置取 loss
# 4. 对有效位置求平均
```

- `ignore_index` 的实现就是**布尔掩码**：内部把 `target == -100` 的位置剔除
- 平均时分母是**有效位置数**，不是总位置数
- 所以 padding 越多，loss 不会被稀释（只算真正要预测的 token）

## 6. 手动算 vs 模型内部算

```python title="manual-vs-internal.py"
# 手动算（自己控制形状与 ignore_index）
loss_fn = nn.CrossEntropyLoss(ignore_index=-100)
loss = loss_fn(logits.view(-1, vocab_size), labels.view(-1))

# 模型内部算（HF 模型 forward 接 labels）
outputs = model(input_ids=input_ids, labels=labels)
loss = outputs.loss
```

| 方式 | 优点 | 缺点 |
| --- | --- | --- |
| 手动算 | 完全可控，可改形状/ignore_index | 要自己处理 reshape |
| 模型内部算 | 一行搞定，HF 标准接口 | 灵活性低，模型得支持 labels |

::::tip
**何时手动算**：自定义损失（如加辅助 loss）、改 ignore_index、跨多个 logits 算 loss 时。其他情况用模型内部的 `outputs.loss` 更省事。
::::

## 小结

| 语法 | 作用 / 返回 |
| --- | --- |
| `nn.CrossEntropyLoss()(logits, target)` | 标量损失（内部 LogSoftmax + NLLLoss） |
| `ignore_index=-100` | 指定标签值不参与损失（-100 是默认） |
| `logits.view(-1, vocab)` | 把 [b, s, v] 摊平成 [b*s, v] 算 loss |
| `model(input_ids, labels=labels).loss` | HF 模型内部算好的标量损失 |
| `F.log_softmax` + `F.nll_loss` | 手动等价写法（数值稳定） |
