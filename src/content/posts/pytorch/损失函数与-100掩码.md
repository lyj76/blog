# PyTorch 损失函数与 -100 掩码：CrossEntropyLoss

LLM 训练里 labels 总是塞一堆 `-100`，这个约定从哪来？为什么直接传 logits 而不是先 softmax？要回答这些，先得明白**交叉熵到底在度量什么**。

> 归属：**PyTorch · `torch.nn`** —— 损失函数（`CrossEntropyLoss` 属于 `torch.nn`）。

## 1. 交叉熵在度量什么：概念本体

交叉熵是**分类任务的损失**——它度量的是：**模型对"正确类别"有多自信**。

公式（单个样本）：

$$\text{loss} = -\log(p_{\text{正确类}})$$

直觉（正确类是第 0 类，模型给它概率 `p`）：

| 模型对正确类 | p | loss = -log(p) | 含义 |
| --- | --- | --- | --- |
| 很自信 | 0.9 | ≈ 0.1 | 小惩罚，模型做得对 |
| 没把握 | 0.5 | ≈ 0.7 | 中惩罚 |
| 几乎错了 | 0.1 | ≈ 2.3 | 大惩罚，模型搞反了 |

**训练的本质**：把正确类的概率 p 一路推到接近 1——`loss` 就是对"不自信"的惩罚，梯度把模型往"更自信"方向推。

对一批样本：每个样本算 `-log(p_正确类)`，然后**求平均** = 总损失。

## 2. 从 logits 到 p：softmax 的桥梁

模型输出的不是概率，而是**未归一化的分数**（logits）。要把分数变成"各类的概率分布"，用 softmax：

$$p_i = \frac{e^{z_i}}{\sum_j e^{z_j}}$$

于是交叉熵 = `-log(p_正确类)`，其中 p 由 logits 经 softmax 得到。

**关键合成**：把"softmax + 交叉熵"合并，可以直接用 logits 算，而且数值更稳：

```python title="ce-knowledge.py"
import torch
import torch.nn as nn
import torch.nn.functional as F

logits = torch.tensor([[2.0, 1.0, 0.1]])   # [1, 3]：三个类的原始分数
target = torch.tensor([0])                  # 正确类 = 第 0 类

# 三种写法，数学上等价：
loss1 = nn.CrossEntropyLoss()(logits, target)          # ① 官方封装
loss2 = F.nll_loss(F.log_softmax(logits, dim=-1), target)  # ② 手动拆开（内部等价）
```

- `CrossEntropyLoss` 内部 = **`LogSoftmax` + `NLLLoss`** 一步到位
- 输入 `logits` 形状 `[batch, num_classes]`，`target` 形状 `[batch]`（正确类索引）

::::important
**别再手动 softmax**：`CrossEntropyLoss` 内部已经做了 `log(softmax(...))`。你如果先 `softmax(logits)` 再传进去，等于 softmax 做了**两次**，结果完全错误。**直接传原始 logits**。
::::

## 3. 数值稳定性：为什么用 log_softmax

`softmax` 里有 `e^z`，当 logits 很大时（如 z=100），`e^100` **上溢成 inf**：

```python title="softmax-stability.py"
def softmax(x):                                    # 朴素版：大数会爆
    return x.exp() / x.exp().sum(dim=-1, keepdim=True)

def log_softmax(x):                                # 稳定版：先减最大值
    x = x - x.max(dim=-1, keepdim=True).values     # 减 max 后 e^z 最大为 e^0=1
    return x - x.exp().sum(dim=-1, keepdim=True).log()
```

- `log_softmax` 先减最大值再算——**数学等价，但不会上溢**（减完后最大的指数是 `e^0 = 1`）
- `CrossEntropyLoss` 内部用的是稳定的 `log_softmax`，所以直接传多大 logits 都不会炸
- 手算也别用 `log(softmax(x))`：先 softmax 再 log，小概率会被压成 0 → `log(0) = -inf`

## 4. ignore_index=-100：掩码机制

`ignore_index` 是 `CrossEntropyLoss` 的一个参数：**指定某个标签值，让它在损失计算中被跳过**。默认值就是 `-100`。

```python title="ignore-index.py"
loss_fn = nn.CrossEntropyLoss(ignore_index=-100)   # 标签为 -100 的位置不参与
```

**它内部做的是掩码**（这正是 LLM 里 -100 的机制）：

```
labels = [10, 20, -100, 30, -100]
            ↑   ↑         ↑
          参与  参与  被跳过  参与  被跳过

mask = labels != -100  →  [T, T, F, T, F]
对 mask=True 的位置算 loss，然后对"有效位置"求平均（分母 = 有效数，不是总数）
```

- 平均的分母是**有效位置数**——所以 padding 越多，loss 不会被稀释
- **为什么是 -100 而不是 0 或 -1**：0 是合法类别索引（词表第 0 个 token），-1 也可能被当索引用；`-100` 是永远不会与合法类别冲突的**哨兵值**

## 5. LLM 场景：展平 + 掩码

LLM 输出 `[batch, seq, vocab]`——每个位置都是"一次词表分类"。`CrossEntropyLoss` 要求 logits 末维是类别数、前面任意，所以**摊平前两维**再算：

```python title="llm-loss-shape.py"
logits = outputs.logits        # [4, 256, 50257]：batch, seq, 词表
labels = batch["labels"]       # [4, 256]：每个位置的正确 token id

loss = nn.CrossEntropyLoss(ignore_index=-100)(
    logits.view(-1, logits.size(-1)),   # [1024, 50257]：摊平成"位置 × 词表"
    labels.view(-1),                    # [1024]：摊平成"位置"
)
```

```
view 摊平（把 batch 和 seq 两维并成一维）：
    logits: [4, 256, 50257]  →  [4×256, 50257]   = 每个位置对词表的打分
    labels: [4, 256]         →  [4×256]          = 每个位置该预测成哪个 token
```

- `-100` 的掩码在这里发挥作用：**padding 位置和 prompt 位置都填 `-100`**，模型只对真正要生成的 token 算损失（prompt 部分让它学"续写答案"而不是"复述 prompt"，见「CausalLM 前向契约」篇）
- HF 模型内部就是按这个逻辑算的：`model(input_ids, labels=labels).loss` 一行搞定（见「CausalLM 前向契约」篇）

| 知识 | 要点 |
| --- | --- |
| 交叉熵是什么 | `-log(p_正确类)`——度量"对正确类多自信"，训练 = 把它推到接近 1 |
| 为什么传 logits | 内部 = LogSoftmax + NLLLoss 一步到位，再手动 softmax 等于做两次 |
| 为什么数值稳定 | log_softmax 先减最大值，不会上溢 |
| `ignore_index=-100` | 掩码机制：跳过指定标签值，分母 = 有效位置数 |
