# PyTorch 自动求导与梯度：计算图 / backward / 梯度管理

训练时为什么每步都要 `optimizer.zero_grad()`？为什么 `loss.backward()` 之后 `.grad` 才有值？这篇把自动求导的内部机制讲透。

> 归属：**PyTorch · `torch.autograd`** —— 自动求导是 PyTorch 的内核机制。

## 1. 计算图与叶子结点

自动求导的核心是把「运算历史」记成一张**计算图**。以 `L = (2A)²` 为例，正向执行时 PyTorch 建出三个节点：

```python title="leaf-example.py"
import torch

A = torch.tensor([3.0], requires_grad=True)   # 用户直接创建 → 叶子
W = 2 * A                                     # 运算产生 → 非叶子
L = W ** 2                                    # 再往后一层

print(A.is_leaf, W.is_leaf)   # True False
print(W.grad_fn)              # <MulBackward0> —— 指向"谁生成了我"
```

图长这样（每条边是一次运算）：

```
A = 3.0 ──(×2)──▶ W = 6.0 ──(平方)──▶ L = 36.0
grad_fn=None        grad_fn=MulBackward0   grad_fn=PowBackward0
```

**每个节点存了两样东西**：
- **前向结果**：A=3.0、W=6.0、L=36.0（就是张量的值）
- **grad_fn**：指向"生成我的运算"。关键在——**每个运算都知道自己怎么求导**：`MulBackward0` 知道 `dW/dA = 2`，`PowBackward0` 知道 `dL/dW = 2W`。这就是"自动求导"的"自动"所在：局部导数不用你算，运算自带

- **叶子结点**：用户直接创建（A、模型参数），`grad_fn = None`，是**梯度更新的最终落点**
- **非叶子结点**：由运算产生（W、L），有 `grad_fn`，默认不保留 `.grad`
- `requires_grad=True` 才被记进计算图；`detach()` 产生新叶子，切断联系

## 2. backward()：沿着图一步步"乘回去"

`L.backward()` 不是魔法——它就是**从 L 出发，逆着边往回走，每过一个节点做一次「上游梯度 × 局部导数」**。这正是链式法则的机械执行：

```
反向过程（三条边倒着走）：

      A=3.0 ──(×2)──▶ W=6.0 ──(平方)──▶ L=36.0
       ▲                ▲                ▲
  ③ 24 落进 A.grad  ② 12 传到 W     ① 从这里发起

① L 节点：局部导数 dL/dW = 2W = 2×6 = 12
   自身是起点，上游梯度 = 1 → 传给 W 的梯度 = 1 × 12 = 12

② W 节点：局部导数 dW/dA = 2
   上游梯度 12 × 局部导数 2 = 24 → 传给 A

③ A 是叶子（没有 grad_fn，不用再传）→ 24 落进 A.grad
```

```python title="backward-example.py"
L.backward()
print(A.grad)   # tensor([24.])   ← 就是第 ③ 步算出的 24
print(W.grad)   # None            ← 非叶子：12 只是"路过"，乘完就丢，不保留
```

**每一步的「上游梯度 × 局部导数」合起来就是链式法则**：

$$\frac{\partial L}{\partial A} = \frac{\partial L}{\partial W} \cdot \frac{\partial W}{\partial A} = 12 \times 2 = 24$$

- `backward()` 必须从**标量**张量调用（多元素张量需传 `gradient` 参数）
- 局部导数由 `grad_fn` 背后的 `*_Backward` 函数**预编译提供**，反向时按节点取用——你只管建图，求导是自动的
- 非叶子结点（W）的梯度**用完即丢**（`None`）：它只负责把梯度乘给上游，自己不留，省内存

## 3. 谁可以调 backward：不只有 loss

任何「背着计算图（有 `grad_fn`）的标量张量」都能发起反向——`loss` 只是最常用的那个（它恰好是前向的终点）：

```python title="who-can-backward.py"
A = torch.tensor([3.0], requires_grad=True)
W = 2 * A            # W 有 grad_fn（MulBackward0）
W.backward()         # 非 loss 也能反向 → 局部导数 dW/dA = 2
print(A.grad)        # tensor([2.])
```

- 发起反向的条件只有两个：**有 `grad_fn`**（是运算的产物）+ **单元素**（标量或单元素张量）
- `loss` 没有特殊地位——任何中间张量满足条件都能发起，它会从自己开始沿图往回乘
- **叶子是落点，不是发起者**：叶子没有 `grad_fn`，对它反向没有图可走——梯度是"流到"叶子上的，不是"从"叶子出发的
- 多元素张量想反向必须传 `gradient` 参数（给每个元素指定权重），训练里用不到

## 4. .grad 是累加器：梯度为什么会累积

`.grad` 是**累加器**，不是赋值器——每次 `backward()` 都把新梯度**加到**已有的 `.grad` 上：

```python title="grad-accumulate.py"
A = torch.tensor([3.0], requires_grad=True)
L = (A ** 2).sum()

L.backward(retain_graph=True)   # 第一次反向（保留计算图，才能反第二次）
print(A.grad)   # tensor([6.])    第一次：0 + 6

L.backward()                    # 第二次反向
print(A.grad)   # tensor([12.])   第二次：6 + 6 → 累加！不是覆盖
```

::::warning
**默认反完一次图就释放**：`backward()` 默认 `retain_graph=False`——反向后计算图被释放以省内存，**同一张图不能反第二次**（会报 `Trying to backward through the graph a second time`）。上面例子第一次用 `retain_graph=True` 保住了图，才展示得出累加。训练里每步都是新前向、新图，所以不涉及这个问题。
::::

- 设计原因：累加器让**梯度累积**（gradient accumulation）成为可能——小显存模拟大 batch：反 N 次不清零，等效于 batch 扩大 N 倍
- 副作用：训练循环里不主动清零，梯度会越累越大，参数更新方向完全错乱（见下一节）

## 5. zero_grad()：为什么每步必须清零

上一节讲了 `.grad` 是累加器。所以每个训练 step 都要先清空梯度，否则新旧梯度累加、更新方向就错了：

```python title="zero-grad.py"
optimizer.zero_grad()   # 清空所有参数的 .grad（等价写法：param.grad = None）
```

- **机制**：`zero_grad()` 遍历优化器里的所有参数，把 `.grad` 置为 `None`（`set_to_none=True` 是默认，比原地清零更省显存）
- **为什么是 None 而不是 0**：`.grad` 置 `None` 后 PyTorch 能复用这块显存，等下一次 `backward()` 时才重新分配
- **完整训练姿势**：`zero_grad → backward → step` 三步的顺序与原因见「优化器内部」篇——这篇只管"为什么要清零"

::::warning
**`zero_grad()` 不是可选步骤**：漏掉它，`backward()` 算出的梯度会和历史梯度累加，参数更新方向完全错乱。
::::

## 6. retain_grad()：查看中间梯度

非叶子结点默认不保留 `.grad`，调试时想看就显式调用：

```python title="retain-grad-example.py"
A = torch.tensor([3.0], requires_grad=True)
W = 2 * A
W.retain_grad()        # 显式要求保留 W.grad
L = W ** 2

L.backward()
print(W.grad)   # tensor([12.]) —— 现在能看到了
```

- `retain_grad()` 必须在 `backward()` **之前**调用
- 只用于调试，正式训练别开（多存一份中间梯度，显存翻倍）
- 链式法则验证：`dL/dW = 2W = 4A = 12`，`dW/dA = 2`，`dL/dA = 12 * 2 = 24` ✓

## 7. with torch.no_grad()：推理上下文

```python title="no-grad-example.py"
model.eval()
with torch.no_grad():
    logits = model(input_ids)   # 前向，但不建计算图
# logits.grad_fn is None —— 不追踪梯度
```

- `no_grad()` 上下文里所有运算**不记录到计算图**，`grad_fn` 为 `None`
- 推理/评估时必用：省显存、加速、避免误调用 `backward()`
- 等价写法：`@torch.no_grad()` 装饰器

::::tip
**`model.eval()` 与 `no_grad()` 是两件事**：`eval()` 切换模块的 `training` 标志（影响 Dropout / BatchNorm 行为）；`no_grad()` 关闭计算图追踪。推理时**两个都要**：`eval()` 改行为，`no_grad()` 省显存。
::::

## 小结

| 语法 | 作用 / 返回 |
| --- | --- |
| `A.is_leaf` / `A.grad_fn` | 是否叶子结点 / 谁生成了我（计算图结构） |
| `L.backward()` | 沿计算图反向，把梯度累加到叶子 `.grad` |
| 谁可以发起 backward | 任何有 `grad_fn` 的标量张量（loss 只是最常用的；叶子是梯度落点） |
| `.grad` 累加 | 每次 backward 累加不清零（梯度累积的底层机制） |
| `optimizer.zero_grad()` | 清空所有参数 `.grad`（`set_to_none`，防累加） |
| `W.retain_grad()` | 让非叶子 `W` 也保留 `.grad`（调试用） |
| `with torch.no_grad():` | 关闭计算图追踪（推理用） |
