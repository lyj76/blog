# PyTorch 参数初始化：nn.init 全掌握

模型参数不能全零开始（梯度对称问题），也不能随意乱来——初始化方式直接影响训练能否收敛。LoRA 的 A/B 矩阵初始化就是一个典型例子。

> 归属：**PyTorch · `torch.nn.init`** —— 初始化方法属于 `torch.nn`。

## 1. 为什么需要初始化

### 1.1 全 0 会怎样：对称性失效（手算推导）

用一个隐藏层两个神经元演示。假设两个神经元的权重都是 0，输入 `x = [1, 2]`：

```
输入 x = [1, 2]
         │        ┌──────────────────────────┐
         ├──×0──▶ │ 神经元 A：z = 1·0 + 2·0 = 0 │
         │        └──────────────────────────┘
         │        ┌──────────────────────────┐
         └──×0──▶ │ 神经元 B：z = 1·0 + 2·0 = 0 │
                  └──────────────────────────┘
```

A 和 B 的输出相同（都是 0）。反向传播时梯度也相同——**权重相同、输入相同、上游梯度相同**，三个条件都相同，梯度必然一样。于是更新一步之后，A、B 的权重**依然完全相同**。

**结论**：两个神经元永远是"对称双胞胎"，训练学不出任何区别——整个层退化成只有一个神经元在工作，模型容量白丢一半。这就是**对称性问题**：全 0 初始化让梯度更新永远无法打破对称。

### 1.2 太大 / 太小会怎样

- **参数太大** → 前向信号逐层放大 → 指数级爆炸 → 梯度爆炸，训练震荡或直接 NaN
- **参数太小** → 信号逐层衰减 → 指数级消失 → 梯度消失，参数几乎不动
- 两个方向的数学根源都是**多层连乘**：每层放大超过 1 倍就爆炸、小于 1 倍就消失——深度网络里指数效应叠加，问题更严重

### 1.3 好的初始化长什么样

**让前向传播的信号方差基本不变**（每层输出和输入"差不多大"），梯度就能稳定回传——第 2 节的 Kaiming / Xavier 系列就是按"保持方差"设计的。

## 2. `nn.init` 常用方法

```python title="init-import.py"
import torch.nn as nn
import torch
```

| 方法 | 分布 | 用途 |
| --- | --- | --- |
| `nn.init.kaiming_uniform_(tensor, a=math.sqrt(5))` | 均匀分布 | 配合 ReLU 系列激活，默认推荐 |
| `nn.init.kaiming_normal_(tensor)` | 正态分布 | 同上，正态版 |
| `nn.init.xavier_uniform_(tensor)` | 均匀分布 | 配合 tanh / sigmoid |
| `nn.init.normal_(tensor, mean=0, std=1)` | 正态分布 | 通用 |
| `nn.init.zeros_(tensor)` | 全 0 | 偏置、LoRA 的 B 矩阵 |
| `nn.init.ones_(tensor)` | 全 1 | 特殊场景 |

::::note
**命名规律**：方法名 = `分布名 + 下划线`。**下划线结尾表示原地修改**（in-place）——直接改传入的张量并返回它，不用接收返回值。
::::

## 3. 标准用法：先 `torch.empty` 再 `init`

```python title="standard-pattern.py"
self.weight = nn.Parameter(torch.empty(in_features, out_features))
nn.init.kaiming_uniform_(self.weight, a=math.sqrt(5))
```

- `torch.empty(形状)`：只分配内存、**不初始化**（里面是垃圾值，必须马上 init）
- `nn.init.xxx_(tensor)`：把随机数填进去

`torch.empty` + `nn.init` 两步是 PyTorch 内部的标准做法。

## 4. LoRA 的 A/B 初始化（重要案例）

```python title="lora-init-example.py"
self.LoRA_A = nn.Parameter(
    nn.init.kaiming_uniform_(torch.empty(r, in_features, dtype=param_dtype), a=math.sqrt(5))
)
self.LoRA_B = nn.Parameter(
    torch.zeros(out_features, r, dtype=param_dtype)
)
```

**为什么这样配：**

| 矩阵 | 初始化 | 原因 |
| --- | --- | --- |
| `A`（r × in） | `kaiming_uniform_` | 降维矩阵，需要合理随机分布保证信号流通 |
| `B`（out × r） | `zeros_`（全 0） | **关键**：B 全 0 时旁路输出 `x @ A.T @ B.T = 0`，合并后 `W = W0 + 0 = W0`——**初始等价原模型，训练不破坏已有能力** |

::::important
**LoRA 必须 B 初始为 0**：如果 A/B 都随机初始化，注入 LoRA 那一刻模型输出就变了（相当于没训练就先破坏了权重）。B=0 保证「注入前后模型行为完全一致」，训练从原始能力出发。
::::

## 5. dtype 一致性（易错点）

```python title="dtype-example.py"
param_dtype = self.original_linear.weight.dtype   # 拿原层精度
self.LoRA_A = nn.Parameter(torch.empty(r, in_features, dtype=param_dtype))
```

新建参数时**必须继承原层的 `dtype`**（如 bfloat16）。若默认 float32 而模型是 bf16，GPU 前向时 `x @ LoRA_A.T` 直接 dtype 冲突报错。

## 小结

| 语法 | 作用 |
| --- | --- |
| `torch.empty(形状)` | 只分配内存（垃圾值） |
| `nn.init.kaiming_uniform_(tensor, a=...)` | ReLU 友好初始化（原地） |
| `nn.init.zeros_(tensor)` | 全 0 初始化 |
| 下划线结尾 | 原地修改，不用接收返回值 |
| LoRA：A 随机、B 全 0 | 保证注入后模型行为不变 |
