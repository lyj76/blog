# PyTorch 设备与精度：.to(device) / dtype / 可复现性

模型在 CPU 还是 GPU？参数是 float32 还是 bfloat16？这两个问题搞错，代码立刻报错。这篇把设备、精度、随机种子三件事一次讲清。

## 1. .to(device)：递归搬运

```python title="to-device-example.py"
import torch
import torch.nn as nn

device = "cuda" if torch.cuda.is_available() else "cpu"
model = nn.Linear(10, 5)
model = model.to(device)        # 模型所有参数一起搬到 device

x = x.to(device)                # 输入张量也要搬
y = model(x)                    # 同设备才能算
```

- `model.to(device)` 是**递归**的：所有 `nn.Parameter` 与 buffer 都跟着搬，子模块也一起搬
- 输入张量**必须单独搬**：`model.to("cuda")` 不会自动把后续传入的 `x` 也搬
- `tensor.to(device)` 返回新张量（非原地）；`model.to(device)` 是原地修改

::::warning
**最常见的报错**：`RuntimeError: Expected all tensors to be on the same device`。原因就是模型在 GPU、输入还在 CPU（或反过来）。检查方法：`print(model.weight.device, x.device)`。
::::

## 2. CPU/GPU 混用报错

```python title="mixed-device-error.py"
model = model.to("cuda")
x = torch.randn(4, 10)          # 还在 CPU
y = model(x)                    # RuntimeError: Expected all tensors to be on the same device
```

- 两个张量做运算必须**同设备**：CPU + CPU、GPU + GPU
- 跨设备运算会触发隐式拷贝，PyTorch 默认不这么做，直接报错
- 解法：把输入也 `.to("cuda")`，或把模型留在 CPU

## 3. dtype 体系

```python title="dtype-example.py"
torch.float32     # 默认浮点，32 位
torch.bfloat16    # brain float，16 位（LLM 训练常用）
torch.float16     # 半精度，16 位
torch.int64       # 长整型，64 位（索引、标签默认）
torch.bool        # 布尔（掩码）
```

| dtype | 用途 | 备注 |
| --- | --- | --- |
| `float32` | 默认训练精度 | 数值稳定，显存占用大 |
| `bfloat16` | LLM 训练/推理 | 同 float32 的指数范围，精度低但不易溢出 |
| `float16` | 推理 | 精度低、易溢出，需配合梯度缩放 |
| `int64` | 索引、标签 | `input_ids` / `labels` 默认就是这个 |

::::note
**`bfloat16` vs `float16`**：两者都是 16 位，但 bfloat16 牺牲精度换指数位（与 float32 同范围），所以不容易出现 inf/nan，更适合训练。LLM 几乎都用 bfloat16。
::::

## 4. dtype 不一致报错

```python title="dtype-mismatch-error.py"
model = nn.Linear(10, 5).to(torch.bfloat16)   # 参数 bf16
x = torch.randn(4, 10)                        # 默认 float32
y = model(x)                                  # RuntimeError: mat1 and mat2 must have the same dtype

# 解法：输入也转 bf16
x = x.to(torch.bfloat16)
y = model(x)                                  # OK
```

- 矩阵乘法要求两边 `dtype` **完全相同**，不会自动转换
- 模型 bf16、输入 float32 是最常见的冲突
- 标签 `int64` 与 logits `float32` 不冲突，因为 `CrossEntropyLoss` 内部会处理

## 5. .item()：标量张量转 Python 标量

```python title="item-example.py"
loss = model(input_ids, labels).loss   # 标量张量（0 维）
loss_value = loss.item()              # Python float
print(f"loss: {loss_value:.4f}")      # 直接用于格式化
```

- `.item()` 把 0 维张量转成 Python `float` / `int`
- 训练日志里 `loss.item()` 是标准写法，避免把张量留在计算图里
- 多元素张量不能直接 `.item()`，先 `.sum()` 或 `.mean()` 压成标量

::::warning
**别用 `loss` 直接打印**：`print(loss)` 会输出 `tensor(0.5432, grad_fn=...)`，既难读又把张量留在图里。永远 `.item()` 取标量再打印。
::::

## 6. .cpu()：搬回 CPU

```python title="cpu-example.py"
logits = model(input_ids)            # 在 GPU
logits_cpu = logits.cpu()            # 搬回 CPU
pred = logits_cpu.argmax(dim=-1)     # CPU 上做索引更方便
```

- `.cpu()` 等价 `.to("cpu")`，把张量从 GPU 拷回 CPU
- 跨设备后想用 numpy、想保存到磁盘、想打印数值，都得先 `.cpu()`
- GPU 张量不能直接 `.numpy()`，必须先 `.cpu()`

## 7. 可复现性：manual_seed

```python title="seed-example.py"
torch.manual_seed(42)
a = torch.randn(3)

torch.manual_seed(42)
b = torch.randn(3)
print(torch.equal(a, b))   # True —— 同种子同结果
```

- `torch.manual_seed(seed)` 设定 PyTorch 随机数生成器的种子
- 同种子 → 同随机序列 → 模型初始化、数据打乱都可复现
- GPU 还需 `torch.cuda.manual_seed_all(seed)`，DataLoader 需给 `generator`

```python title="seed-full.py"
def set_seed(seed=42):
    torch.manual_seed(seed)
    torch.cuda.manual_seed_all(seed)
    torch.backends.cudnn.deterministic = True   # 牺牲速度换确定性
    torch.backends.cudnn.benchmark = False
```

::::tip
**何时需要可复现**：调试时（确认改动有效）、对比实验时（公平比较）。正式训练通常关掉 `deterministic`，让 cudnn 自动选最快算法。
::::

## 小结

| 语法 | 作用 / 返回 |
| --- | --- |
| `model.to(device)` | 递归搬所有参数到 device（原地） |
| `x.to(device)` | 搬张量到 device（返回新张量） |
| `x.to(torch.bfloat16)` | 转精度 |
| `loss.item()` | 标量张量 → Python float |
| `x.cpu()` | GPU 张量搬回 CPU |
| `torch.manual_seed(seed)` | 设随机种子，保证可复现 |
