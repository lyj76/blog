# PyTorch 优化器内部：params / param_groups / state

`optimizer = AdamW(trainable_params, lr=3e-4)` 这一行背后是三个数据结构：params 列表、param_groups、state。理解它们，优化器就不再是"魔法"。

> 归属：**PyTorch · `torch.optim`** —— 优化器（`from torch.optim import AdamW`）。

## 1. 优化器能输入什么：params 与超参数

`AdamW(第一参数, 超参数...)`——第一参数可以是**任意可迭代的 Tensor / Parameter 集合**，其余全是超参数：

```python title="optimizer-input.py"
from torch.optim import AdamW

# 写法一：全部参数（model.parameters() 是生成器）
optimizer = AdamW(model.parameters(), lr=3e-4)

# 写法二：过滤后的参数列表
trainable = [p for p in model.parameters() if p.requires_grad]
optimizer = AdamW(trainable, lr=3e-4)

# 写法三：param_groups（按组管理，每组可覆盖超参数）
optimizer = AdamW([
    {"params": backbone.parameters(), "lr": 1e-5},   # 骨干：小学习率
    {"params": [lora_a, lora_b],        "lr": 1e-3},   # LoRA：大学习率
], lr=3e-4)   # 未覆盖的组用这个默认 lr
```

**构造时发生了什么**（`AdamW(...)` 内部做的四件事）：

1. **一次性消费参数**：把你传的可迭代对象遍历成参数列表——`model.parameters()` 是生成器，**用一次就空了**，所以构造之后不能再拿它干别的
2. **去重 + 校验**：重复的参数只留一份；每个参数必须是带 `requires_grad=True` 的 Tensor/Parameter，否则报错
3. **包成 param_groups**：写法一/二（裸参数列表）自动包成**一个**默认组；写法三每个字典单独成组（见第 3 节）
4. **存超参**：超参数进 `optimizer.defaults`（组级默认配置），每个组的 `param_groups[i]` 里也各存一份

| 输入 | 类型 | 说明 |
| --- | --- | --- |
| 第一参数 `params` | 可迭代的 Tensor/Parameter | 要优化的参数（生成器、列表、字典列表都行） |
| `lr` | float | 学习率（必给，无默认值） |
| `betas` | `tuple[float, float]` | Adam 家族：一阶 / 二阶矩指数衰减系数 |
| `eps` | float | 防止除零的小常数 |
| `weight_decay` | float | 权重衰减（AdamW 为解耦形式） |

## 2. trainable_params 的数据结构：Parameter 列表

```python title="trainable-params.py"
trainable = [p for p in model.parameters() if p.requires_grad]
type(trainable)      # list
type(trainable[0])   # torch.nn.parameter.Parameter（Tensor 子类）
```

- **类型**：`list[nn.Parameter]`。`nn.Parameter` 是 `Tensor` 的子类，只是默认 `requires_grad=True` 并注册进 Module
- **过滤原理**：`if p.requires_grad` 筛掉冻结参数，剩下的才是要训练的参数
- **关键：优化器持有的是引用，不是拷贝**。`step()` 原地修改 `param.data`，训练才真正改到模型里的参数——如果传的是拷贝，训练就不会生效
- **为什么只传参数就够了**：前向用参数算出 loss → `backward()` 把梯度填进每个参数的 `.grad` → 优化器**读 `.grad`、改 `.data`**，闭环完成

（参数的注册与结构见「nn.Module 与参数管理」篇；梯度的产生见「自动求导与梯度」篇。）

## 3. param_groups：按组管理参数

`param_groups` 是优化器内部最核心的数据结构——**一个 `list[dict]`**：

```python title="param-groups.py"
optimizer = AdamW(model.parameters(), lr=3e-4, weight_decay=0.01)
print(optimizer.param_groups)
# [{'params': [<Parameter ...>, ...], 'lr': 0.0003, 'betas': (0.9, 0.999),
#   'eps': 1e-08, 'weight_decay': 0.01, 'amsgrad': False, ...}]
```

**传裸参数列表 → 自动包成一个组**：写法一/二（`AdamW(参数列表, ...)`）在内部被包成**只有一个元素的 param_groups**——那个列表里装着你传的所有参数。写法三（传字典列表）则每个字典独立成组，所以 `param_groups` 有多个元素。

- 每个 dict = 一组参数 + 这组的超参数；**不指定的项继承 `defaults`**
- `optimizer.param_groups[0]['lr']`：当前学习率——**学习率调度器改的就是这里**（见下文第 6 节）
- 多组场景：骨干和 LoRA 用不同 lr、冻结与解冻切换
- `add_param_group()`：训练中途加一组（如解冻某个模块后把它加入训练）：

```python title="add-param-group.py"
optimizer.add_param_group({"params": [head.weight], "lr": 1e-4})
```

## 4. state：优化器状态字典

`state` 是**优化器"记住"的东西**：Adam 更新参数时不只看当前梯度，还要用每个参数**历史梯度**的统计量（动量 m、方差 v）来决定更新幅度。这些历史统计存在 `state` 里——丢了它，Adam 每步都从零开始。

**先跑一遍看它长什么样**（一个 3 元素参数，走完一步训练）：

```python title="state-example.py"
import torch
from torch.optim import AdamW

w = torch.nn.Parameter(torch.tensor([1.0, 2.0, 3.0]))
optimizer = AdamW([w], lr=1e-3)

print(optimizer.state)          # 还没 step → defaultdict(<class 'dict'>, {})，空的

loss = (w * 2).sum()            # 梯度 = [2, 2, 2]
loss.backward()
optimizer.step()

print(optimizer.state)          # step 之后才有内容（见下）
```

step 之后，`optimizer.state` 变成这样：

```
optimizer.state = defaultdict(dict)
│
├── <参数对象 w> ──▶ {
│       'step':       tensor(1),                    ← 更新过 1 次
│       'exp_avg':    tensor([0.2, 0.2, 0.2]),      ← 一阶矩 m（动量）
│       'exp_avg_sq': tensor([0.004, 0.004, 0.004]) ← 二阶矩 v（方差）
│   }
│
└── <参数对象 #2> ──▶ { ... }     ← 有几个参数就有几个槽
```

**两层嵌套**：
- **外层**：`defaultdict`，key 是**参数对象本身**，value 是该参数的优化状态
- **内层**：三个字段——含义和形状见下表：

| 字段 | 含义（Adam） | 形状 |
| --- | --- | --- |
| `step` | 该参数被更新了几次（用于偏差修正） | 标量 `[]` |
| `exp_avg` | 一阶矩 m：梯度的滑动平均（动量） | **同参数** |
| `exp_avg_sq` | 二阶矩 v：梯度平方的滑动平均（自适应步长分母） | **同参数** |

**两个"为什么"**：
- **为什么 key 是参数对象**：优化器收到的是参数对象列表，必须把"每个参数"和"它的历史"对上——Tensor 按**身份（id）**哈希，值变了也能找到，所以对象就是最稳定的钥匙
- **为什么 m、v 和参数同形状**：它们是**逐元素**统计——参数 3 个元素，每个元素都有自己的动量和方差，`[3]` 对 `[3]`

**它在 step() 里怎么被用**（Adam 的更新公式）：

```python title="adam-update.py"
m = β1 * m + (1 - β1) * g        # 读 exp_avg 更新动量
v = β2 * v + (1 - β2) * g²       # 读 exp_avg_sq 更新方差
param -= lr * m / (√v + ε)       # 改 .data
```

这就是第 5 节 `step()` 循环里"第⑤步建槽、第⑥步用状态更新"的具体内容——**state 就是 m 和 v 的存放处**。

**续训为什么必须存它**：`optimizer.state_dict()` 把 `{'state': ..., 'param_groups': [...]}` 一起序列化，`load_state_dict()` 恢复——否则动量和方差归零，Adam 从零开始累计，续训效果打折扣。

## 5. 核心方法：step() 与 zero_grad() 的内部过程

### step()：一次"读梯度、更新参数"的遍历

`step()` 不是魔法——它就是**两层循环**：遍历每组 → 遍历组内每个参数，对每个参数做"读 `.grad` → 更新 `state` → 改 `.data`"：

```python title="step-internals.py"
# step() 的实际机制（伪代码）：
for group in optimizer.param_groups:              # ① 外层：遍历每组
    lr = group["lr"]                               #    取这组的超参数
    for p in group["params"]:                      # ② 内层：遍历组内每个参数
        if p.grad is None:                         # ③ 跳过没有梯度的参数（冻结/没 backward）
            continue
        grad = p.grad                              # ④ 取梯度（backward 刚填好的）
        if p not in optimizer.state:               # ⑤ 第一次见到这个参数 → 初始化状态槽
            optimizer.state[p] = {}                #    （Adam 首次会建 step/exp_avg/exp_avg_sq）
        state = optimizer.state[p]
        # ⑥ 按优化算法更新状态 + 参数（以 Adam 为例，见第 4 节公式）
        m = β1 * m + (1 - β1) * grad               #    更新动量
        v = β2 * v + (1 - β2) * grad ** 2          #    更新方差
        p.data -= lr * m_hat / (√v_hat + ε)        #    原地改 .data
```

配合一次训练闭环看（`zero_grad → backward → step`）：

```
① zero_grad()：所有 .grad 清空
② backward() ：所有 .grad 被填上（梯度）
③ step()     ：读到 .grad → 更新 state → 改 .data   ← 本方法
```

**这就是为什么 step() 不改 `.grad`**：它只"消费"梯度。下一个 step 之前必须 `zero_grad()` 清掉旧梯度，否则累加。

### zero_grad()：把梯度置 None 而非 0

```python title="zero-grad-internals.py"
# zero_grad() 的实际机制（伪代码）：
for group in optimizer.param_groups:
    for p in group["params"]:
        if p.grad is not None:
            p.grad = None          # 默认 set_to_none=True
```

- **为什么置 `None` 而不是 `tensor(0.)`**：`None` 让 PyTorch 把这块梯度显存**归还给内存池**，下次 `backward()` 再重新分配；置 `0` 则保留一个全零张量一直占着显存
- 作用范围：只清优化器**持有的参数**——冻结的参数不在 `param_groups` 里，它们的 `.grad` 本就不该存在

### 其他方法

| 方法 | 作用 |
| --- | --- |
| `state_dict()` / `load_state_dict()` | 保存 / 恢复优化器状态（续训用） |
| `add_param_group()` | 动态增加一组参数 |

### 属性速查

| 属性 | 结构 | 说明 |
| --- | --- | --- |
| `param_groups` | `list[dict]` | 参数与每组的超参数（scheduler 改 lr 的地方） |
| `defaults` | `dict` | 默认超参数 |
| `state` | `defaultdict` | 每参数的优化历史状态 |

::::note
**`step()` 是"读梯度、改数据"，不是"算梯度"**：梯度由 `loss.backward()` 产生并填进 `.grad`，优化器只消费它。所以顺序必须是 `zero_grad → backward → step`（顺序原因见「自动求导与梯度」篇）。
::::

## 6. 训练循环配套：梯度裁剪与学习率调度

这两个操作都发生在 `step()` 的前后，和优化器直接相关：

**梯度裁剪**（防梯度爆炸）：在 `backward` 之后、`step` 之前调用

```python title="clip-grad.py"
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)   # 全局梯度范数超限就按比例缩放
optimizer.step()
```

**学习率调度器**（训练中调低 lr）：持有优化器引用，改的是 `param_groups[0]['lr']`

```python title="lr-scheduler.py"
from torch.optim.lr_scheduler import StepLR

scheduler = StepLR(optimizer, step_size=5, gamma=0.5)   # 每 5 轮 lr *= 0.5
# 每个 epoch 末调一次（不是每个 step）：
scheduler.step()
```

（`loss.item()` 打日志见「设备与精度管理」篇；f-string 见「f-string 格式化」篇。）

## 7. 只优化部分参数：LoRA 场景

过滤可训练参数是构造 `trainable_params` 的核心套路：

```python title="filter-params.py"
trainable_params = [p for p in model.parameters() if p.requires_grad]
optimizer = AdamW(trainable_params, lr=3e-4)
```

- 冻结的参数（`requires_grad=False`）**根本不进优化器**——`step()` 不会碰它们，`backward()` 也不会给它们存梯度
- 列表推导式把"全部参数"过滤成"可训练参数"，这一步产出的就是第 2 节的 `trainable_params`
- LoRA 标准写法：原模型整体 `requires_grad=False`，只把 A / B 矩阵交给优化器
- 打印"只训了百分之几"用 `numel()` 统计（参数元素数）：

```python title="trainable-stats.py"
trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
total = sum(p.numel() for p in model.parameters())
print(f"可训练占比: {100 * trainable / total:.4f}%")
```

## 小结

| 语法 | 作用 / 数据结构 |
| --- | --- |
| `AdamW(params, lr=...)` | 第一参数是参数集合，其余是超参数（存进 `defaults`） |
| `trainable_params` | `list[nn.Parameter]`，优化器持有引用（读 `.grad` 改 `.data`） |
| `optimizer.param_groups` | `list[dict]`，参数分组 + 组级超参数 |
| `optimizer.state` | `defaultdict`，每参数的 Adam 状态（m / v / step） |
| `optimizer.step()` | 读 `.grad` + `state` → 更新 `param.data` |
| `optimizer.zero_grad()` | 清空 `.grad`（set_to_none） |
| `optimizer.state_dict()` | 保存状态（续训 / 迁移） |
